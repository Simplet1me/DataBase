# 接口文档（REST API）

> 本文档由后端开发实现过程中同步编写，实现完成即文档完成；前端严格按本文档开发页面（见 [03-前端页面方案.md](03-前端页面方案.md)）。
> 数据库对象映射：[procedures.sql](../procedures.sql)（5 个存储过程）、[triggers.sql](../triggers.sql)（3 个触发器）、[views.sql](../views.sql)（4 个视图）。

## 0 通用约定

| 项 | 约定 |
| --- | --- |
| Base URL | `http://localhost:8080/api`（前端 dev 环境经 Vite proxy 转发，见 03 文档） |
| 认证方式 | 登录返回 JWT，请求头 `Authorization: Bearer <token>` |
| 请求/响应格式 | `application/json`，编码 UTF-8 |
| 统一响应 | `{ "code": 0, "message": "success", "data": ... }` |
| 时间格式 | `yyyy-MM-dd HH:mm:ss` |
| 分页 | 列表接口暂不分页（课程设计数据量小）；`data` 直接为数组 |
| 并发控制 | 审批类 UPDATE 一律带原状态条件（如 `WHERE *_status='pending'`），影响行数为 0 时返回 404"该申请已被处理"——防止两名学生会成员并发重复审批 |

**错误码**：`0` 成功｜`400` 参数错误｜`401` 未登录/token 失效｜`403` 无权限｜`404` 不存在｜`1001` 业务校验失败（存储过程 SIGNAL 原文透传）｜`1002` 数据冲突（唯一键）｜`500` 服务器错误。

**身份约定**：登录后由后端实时计算复合身份返回，前端据其渲染菜单：`unionMember`（学生会成员）、`clubRole`（在社角色 president/vice_president/member，未入社为 null）。接口权限标注中的"管理层"= clubRole ∈ {president, vice_president}。

## 1 认证模块

### 1.1 POST /api/auth/login　`公开`
学生/教师统一登录。
```json
// 请求
{ "userType": "student", "account": "2021001", "password": "<SHA-256哈希>" }
// 响应 data
{
  "token": "eyJhbGci...",
  "id": "2021001", "name": "张三", "userType": "student",
  "unionMember": false,
  "club": { "clubId": 1, "clubName": "篮球社", "clubRole": "president" }  // 未入社为 null
}
```
实现要点：按 userType 查 student/teacher 比对哈希；失败统一返回 1001"账号或密码错误"。

### 1.2 GET /api/auth/profile　`已登录`
返回当前登录人信息与复合身份（结构同上，无 token 字段）。

## 2 学生端

### 2.1 GET /api/clubs　`全员`
社团列表。data 为数组，元素来自视图 `v_club_info`：`{ clubId, clubName, clubDesc, clubCreateTime, teaId, teaName, memberCount }`。

### 2.2 GET /api/clubs/{clubId}　`全员`
社团详情（v_club_info 单条）+ 该社团有效公告列表（`is_deleted=0`，按发布时间倒序）。

### 2.3 POST /api/clubs/{clubId}/join-applies　`学生`
提交入社申请，无请求体。
- 实现：`CALL sp_submit_join_apply(clubId, 当前学生)`；SIGNAL 原文透传（1001）："您已加入社团…"／"您已有待审批的入社申请…"／"该社团正在解散审批中…"；
- 响应 data：`{ "applyId": 1 }`。

### 2.4 GET /api/join-applies/my　`学生`
我的入社申请历史：`{ applyId, clubId, clubName, applyTime, applyStatus, replyTime }`（pending/agree/reject）。

### 2.5 GET /api/members/my　`学生`
我的社团档案，来自视图 `v_stu_club_record`（WHERE stu_id=当前学生）：含在社与历史记录 `{ memberId, clubName, memberRole, joinTime, leaveTime, leaveType }`。

### 2.6 POST /api/members/my/quit　`学生`
主动退社，无请求体。
- 实现：`UPDATE club_member SET leave_time=NOW(), leave_type='quit', operate_stu_id=本人`；
- 未在社 → 404；成功 data 返回 `{ "leaveTime": "..." }`。

### 2.7 GET /api/clubs/{clubId}/activities　`该社社员`
本社团活动（`act_status IN ('running','finish')`，开始时间倒序）：`{ actId, actName, actDesc, actStartTime, actEndTime, actPlace, actStatus }`。

### 2.8 GET /api/messages　`全员`
系统消息列表（`is_deleted=0`，发布时间倒序）：`{ msgId, publishStuId, publishName, msgTitle, msgContent, publishTime }`。

## 3 管理层（正/副社长）

> 全部接口校验：当前学生在 clubId 社团的在职角色 ∈ {president, vice_president}，否则 403。正副平权（B4）。

### 3.1 GET /api/clubs/my　`管理层`
我管理的社团：`{ clubId, clubName, clubDesc, clubCreateTime, teaName, memberCount }`（单社团制，data 为对象）。

### 3.2 GET /api/clubs/{clubId}/members　`管理层`
在职社员列表（视图 `v_club_member_detail`）：`{ memberId, stuId, stuName, stuClass, stuPhone, memberRole, joinTime }`。

### 3.3 POST /api/clubs/{clubId}/members/{stuId}/kick　`管理层`
踢出社员，无请求体。
- 校验：目标为在职社员且 `member_role <> 'president'`（社长不可踢）；
- 实现：`UPDATE ... SET leave_time=NOW(), leave_type='kick', operate_stu_id=操作人`。

### 3.4 POST /api/clubs/{clubId}/role-change　`管理层`
晋升/降级/换届。
```json
// 请求
{ "stuId": "2021003", "newRole": "vice_president" }
// 响应 data
{ "oldRole": "member", "newRole": "vice_president" }
```
- 实现：`CALL sp_change_member_role(clubId, stuId, newRole, 当前操作人)`；
- 换届走专用接口 3.4.1（原子换届），本接口仅用于单人晋升/降级。

### 3.4.1 POST /api/clubs/{clubId}/change-president　`社长`
社长换届（B5）：后端事务内"先降后升"，一次提交原子完成。
```json
// 请求
{ "demoteStuIds": ["2021006"], "newPresidentStuId": "2021008" }
// 响应 data
{ "changes": [ { "stuId": "2021006", "oldRole": "president", "newRole": "member" },
               { "stuId": "2021008", "oldRole": "vice_president", "newRole": "president" } ] }
```
- 实现：@Transactional 内先按 demoteStuIds 顺序调 sp_change_member_role 置 member，再调 sp_change_member_role 置新社长 president；任一步失败整体回滚（漏降级原社长导致"已存在在职正社长"时返回 1001 提示）；
- 新社长须为本社团在职社员（SP 校验）；仅社长可发起换届（接口权限校验）。

### 3.5 GET /api/clubs/{clubId}/join-applies　`管理层`
待审批入社申请（视图 `v_join_apply_pending`）：`{ applyId, stuId, stuName, stuClass, stuPhone, applyTime }`。

### 3.6 POST /api/join-applies/{applyId}/audit　`申请所属社团管理层`
审批入社申请。
```json
// 请求
{ "result": "agree" }   // agree | reject
```
- 实现：`UPDATE join_apply SET apply_status=?, approve_stu_id=操作人, reply_time=NOW()`（仅限 pending）；
- agree 时触发器 `trg_join_apply_audit` 自动入社；若学生已在他社（1062）→ 1002"该学生已加入其他社团，审批已回滚"；
- 非 pending 状态再次审批 → 404。

### 3.7 POST /api/clubs/{clubId}/activities　`管理层`
活动申办。
```json
// 请求
{ "actName": "迎新杯", "actDesc": "...", "actStartTime": "2026-10-01 14:00:00",
  "actEndTime": "2026-10-01 18:00:00", "actPlace": "体育馆" }
```
- 校验：该社团无 pending 解散申请（B2 冻结，否则 1001"该社团正在解散审批中"）；
- actStatus 默认 wait_audit；响应 data `{ "actId": 1 }`。

### 3.8 GET /api/clubs/{clubId}/activities/all　`管理层`
全部活动（含 wait_audit/reject）：在 2.7 字段基础上增加 `applyTime`、`auditTeaName`、`auditTime`。

### 3.9 POST /api/clubs/{clubId}/activities/{actId}/finish　`管理层`
活动完结（仅 running → finish）。

### 3.10 社团公告 CRUD　`管理层`
| 方法 路径 | 说明 |
| --- | --- |
| GET /api/clubs/{clubId}/notices | 列表（含软删记录，管理视图；`is_deleted=0` 在前端置灰） |
| POST /api/clubs/{clubId}/notices | 发布 `{ "noticeTitle": "...", "noticeContent": "..." }`，publish_stu_id=操作人 |
| PUT /api/clubs/{clubId}/notices/{noticeId} | 编辑标题/内容 |
| DELETE /api/clubs/{clubId}/notices/{noticeId} | 删除（软删 `is_deleted=1`，C7） |

### 3.11 POST /api/clubs/{clubId}/dissolve-applies　`社长`
发起解散申请，无请求体。
- 实现：`CALL sp_submit_dissolve_apply(clubId, 当前学生)`；SIGNAL 透传："仅社团社长可发起解散申请"／"该社团已有待审批的解散申请…"；
- 响应 data `{ "dissolveApplyId": 1 }`。

### 3.12 GET /api/clubs/{clubId}/dissolve-applies　`管理层`
本社团解散申请记录与审批进度：`{ dissolveApplyId, applyTime, unionAuditStatus, unionAuditTime, teaAuditStatus, teaAuditTime, finalStatus }`。

## 4 学生会

> 全部接口校验 unionMember=true；审批时 `union_audit_stu_id` 写入当前成员学号（C6）。

### 4.1 GET /api/union/create-applies　`学生会`
待审批建团申请：`{ createApplyId, clubName, clubDesc, applyTeaId, applyTeaName, applyTime, initiators: [ { stuId, stuName } ×5 ], unionAuditStatus, teaAuditStatus, finalStatus }`。

### 4.2 POST /api/union/create-applies/{id}/audit　`学生会`
审批建团申请。
```json
{ "result": "agree" }   // agree | reject
```
- 实现：UPDATE union_audit_*；reject 时同时置 `final_status='fail'`；agree 时 final_status 保持 pending（等教师终审）；
- 非 pending → 404。

### 4.3 GET /api/union/dissolve-applies　`学生会`
待审批解散申请：`{ dissolveApplyId, clubId, clubName, applyStuId, applyStuName, applyTime, unionAuditStatus, teaAuditStatus, finalStatus }`。

### 4.4 POST /api/union/dissolve-applies/{id}/audit　`学生会`
审批解散申请（同 4.2，reject 置 final_status='fail'）。

### 4.5 学生会成员管理　`学生会`
| 方法 路径 | 说明 |
| --- | --- |
| GET /api/union/members | 成员列表 `{ stuId, stuName, joinTime }` |
| POST /api/union/members | 新增 `{ "stuId": "2021010" }`（须为学生表中已存在且未在任）→ 写操作日志 add |
| DELETE /api/union/members/{stuId} | 移除：剩余成员 ≥ 1 才允许（C5，否则 1001"学生会至少保留一名成员"）→ 写操作日志 remove |

### 4.6 GET /api/union/audit-records　`学生会`
历史建团审批记录（含 agree/reject/final 状态与双方审批人、时间）；解散审批记录随社团删除不保留（设计决策）。

### 4.7 系统消息管理（发布/编辑/删除）　`学生会`
| 方法 路径 | 说明 |
| --- | --- |
| POST /api/messages | 发布 `{ "msgTitle": "...", "msgContent": "..." }`，publish_stu_id=当前成员 |
| PUT /api/messages/{msgId} | 编辑标题/内容 |
| DELETE /api/messages/{msgId} | 删除（软删 is_deleted=1，C7） |

## 5 教师端

> 教师侧审批仅限"被指定/所属"对象：建团申请仅 `apply_tea_id=当前教师`；解散/活动仅 `club.tea_id=当前教师`（C4）。

### 5.1 GET /api/teacher/create-applies　`教师`
指定我为指导教师的建团申请（含发起人名单、双审状态）。

### 5.2 POST /api/teacher/create-applies/{id}/audit　`被指定教师`
终审建团申请。
```json
{ "result": "agree" }
```
- reject → `tea_audit_status='reject'` + `final_status='fail'`；
- agree 且 union 已 agree → `CALL sp_create_club(id)`（SP 内：双审校验 → 创建社团 → 5 发起人入社 → final_status='success'）；
- agree 但 union 未审 → 仅记录 tea_audit_status='agree'，final_status 保持 pending；
- SP 抛错（发起人已入社/社名重复/教师已被绑定）→ 1001/1002 透传，申请保持 pending。

### 5.3 GET /api/teacher/dissolve-applies　`指导教师`
所辖社团的解散申请列表（含双审状态）。

### 5.4 POST /api/teacher/dissolve-applies/{id}/audit　`指导教师`
终审解散申请：reject → final_status='fail'；agree 且 union 已 agree → `UPDATE final_status='success'` 后 `CALL sp_dissolve_club(id)`（事务删除社团全部数据）。

### 5.5 GET /api/teacher/club　`指导教师`
所辖社团数据总览：社团信息 + 在职社员名单（v_club_member_detail）+ 活动列表 + 公告列表（一次返回或由前端分接口取，建议合并为一个聚合对象）。未绑定社团 → data=null。

### 5.6 GET /api/teacher/activities　`指导教师`
所辖社团待审批活动（act_status='wait_audit'）。

### 5.7 POST /api/teacher/activities/{actId}/audit　`所属社团指导教师`
审批活动：
```json
{ "result": "agree" }   // agree → running（B3）；reject → reject
```
写 `audit_tea_id=当前教师`、`audit_time=NOW()`。
