# 前端页面方案（Vue3 + Element Plus）

> 依据：[02-接口文档.md](02-接口文档.md)。前端严格按接口文档生成页面，接口字段以后端实际返回为准。
> 工程现状：frontend/ 已就绪（Vue 3.5 / vue-router 5.3 / Element Plus 2.14 / Vite 8.3，已配置 unplugin 自动导入组件）。

## 1 需追加的依赖与配置

```bash
cd frontend
npm install axios pinia
```

**vite.config.js 追加代理**（dev 环境转发 /api，避免跨域）：
```js
server: {
  proxy: { '/api': { target: 'http://localhost:8080', changeOrigin: true } }
}
```

## 2 前端目录结构约定

```
frontend/src/
├─ api/            axios 封装 + 按模块拆分的接口函数（auth.js、club.js、union.js、teacher.js、message.js）

```

## 4 页面设计要点

### 4.1 登录页
- 学号/工号 + 密码 + 身份单选（学生/教师）；密码提交前做 SHA-256（前端 crypto-js 或 Web Crypto API，实现阶段定）；
- 登录成功存 token 与身份对象到 pinia + localStorage，跳转 /clubs 或对应工作台。

### 4.2 社团广场
- 卡片列表（el-card：社名、指导教师、人数、简介），点击打开详情抽屉（简介+公告列表）；无"解散"概念（解散即删除）；
- 未入社学生卡片上有"申请加入"按钮（调 2.3，成功后提示进入等待）。

### 4.3 个人中心（学生）
- 档案 Tab：v_stu_club_record 数据（在社卡片 + 历史记录 el-timeline，leave_type 中文映射：kick 被踢出 / quit 主动退社）；
- 申请 Tab：我的申请历史 + 状态标签（pending 待审批 warning / agree 已同意 success / reject 已拒绝 danger）；
- 退社按钮（2.6，二次确认，成功后刷新身份信息）；
- 建团入口（见 4.4）。

### 4.4 建团申请（学生）
- 表单：社名、简介、选择指导教师（下拉：空闲教师列表——接口需后端补充，**待补接口**：GET /api/teachers/free，返回未绑定社团的教师）、5 名发起人学号（自己 + 4 人，可校验无在社记录）；
- 提交：后端校验 5 人 + 教师空闲 + 社名唯一（1001/1002 提示）；
- 审批进度条（el-steps：学生会审批 → 教师审批 → 创建成功/驳回）。

### 4.5 管理层总览/社员管理
- 在职社员表格（el-table）+ 行操作：晋升/降级下拉（调 3.4）、踢出（3.3，确认弹窗）；
- **换届向导（B5）**：一个弹窗内收集"降级名单（原社长及需调整副社长，多选）"+"新社长人选（单选）"，**一次提交**调用换届专用接口（3.4.1），后端事务原子完成"先降后升"；失败时按返回的 1001 原因提示（如漏选原社长降级则提示"已存在在职正社长"）；
- 角色 Tag 色：president 红 / vice_president 橙 / member 默认。

### 4.6 入社审批台
- v_join_apply_pending 表格 + 同意/拒绝按钮（3.6，同意失败 1002 时 el-message.error 展示"该学生已加入其他社团"）；行状态即时刷新。

### 4.7 活动管理
- 申办表单（名称/简介/起止时间/地点，时间选择器仅展示用）；列表按 act_status 过滤（wait_audit 待审批 / running 进行中 / finish 已结束 / reject 已驳回）；running 行有"完结"按钮（3.9）。

### 4.8 公告管理
- 发布/编辑弹窗（el-dialog + el-form）；删除软删（确认弹窗，列表仅管理层视图显示已删除置灰标记）。

### 4.9 解散申请
- 社长可见"发起解散"按钮（3.11，红色危险操作二次确认）；进度条展示双审状态（el-steps）；解散通过后社团消失，前端刷新身份并提示。

### 4.10 学生会工作台
- Tab 1 建团审批：申请卡片（社名、发起人 5 人、指定教师）+ 同意/驳回（4.2）；
- Tab 2 解散审批：同款面板（4.4）；
- Tab 3 成员管理：列表 + 新增（选学生）+ 移除（4.5；剩余 1 人时后端 1001 提示，前端可提前禁用）；
- Tab 4 消息管理：发布/编辑/删除（4.7）；审批记录查询入口（4.6）。

### 4.11 教师工作台
- 待办：建团审批（5.2，同意时后端调 sp_create_club，失败透传原因）、解散审批（5.4）、活动审批（5.7）；
- 所辖社团：5.5 聚合展示（信息/社员/活动/公告）；消息中心入口。

### 4.12 消息中心
- 全员页面：消息列表（标题、内容、发布人、时间），无已读状态（公告制）。

## 5 全局交互与工程约定

1. **axios 封装**（utils/request.js）：baseURL `/api`；请求拦截器注入 Bearer token；响应拦截器统一解包 `code`——0 返回 data，非 0 用 el-message 弹出 message 并 reject（1001 业务提示同样弹出）；401 清 token 跳登录页；
2. **路由守卫**：无 token → /login；有 token 按身份对象渲染菜单（el-menu 动态项）；进入无权限页面跳 /clubs；
3. **状态管理**：pinia 只存 user 身份；列表数据组件内自管，不全局缓存；
4. **状态标签**：统一 StatusTag 组件集中映射枚举中文与颜色（附录 A）；
5. **表单校验**：Element Plus 表单规则，提交前必填校验；危险操作（踢出/解散/删除/驳回）统一二次确认弹窗；
6. **时间**：后端已统一返回 `yyyy-MM-dd HH:mm:ss` 字符串，前端直接展示不转换。
