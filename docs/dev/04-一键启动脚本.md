# 初始化、启动与构建

## 1 前置条件

交付产物运行需要Java17+、Node.js22.12+、已运行的MySQL及mysql客户端。源码构建另需Maven3.6+（或自带mvnw.cmd）和网络。实测MySQL8.4、Java21、Node24；Java编译目标为17。

## 2 首次初始化

在项目根目录运行：

```powershell
node scripts/db.mjs init club_manage
node scripts/db.mjs demo club_manage
```

或依次双击scripts/init-db.bat与scripts/import-demo.bat。初始化严格按sql.sql→triggers.sql→views.sql→procedures.sql执行，路径均在docs/design。初始化发现已有表会停止；导入demo是单独操作，会清理本项目库现有业务数据，适用于首次导入或明确要重置演示时。

默认数据库root/123456，端口3306；可用DB_USER、DB_PASSWORD、DB_HOST、DB_PORT覆盖脚本连接。MYSQL_BIN可设为mysql.exe完整路径。Windows默认自动识别C:/Program Files/MySQL/MySQL Server 8.0/bin/mysql.exe，也可把mysql加入PATH。

脚本处理MySQL8的表/过程参数排序规则继承差异，原SQL文件不改写。详细原因见08文档；不要用原参考文档的直接导入命令跳过此处理。

## 3 一键启动与停止

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start-all.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop-all.ps1
```

也可双击对应start-all.bat/stop-all.bat。

启动脚本检查Java/Node、release/club-manage.jar、8080与5173端口，隐藏运行后端和前端。前端使用Node内置静态服务器托管frontend/dist，/api代理到8080，因此交付产物运行不需要npm install。启动脚本不初始化数据库、不安装依赖。浏览器打开http://localhost:5173，日志在logs/backend.log与logs/frontend.log。

停止脚本核对保存的进程号、程序名及启动时间，仅结束本启动脚本创建且身份匹配的进程。关闭启动提示窗口不会停止后台服务。

## 4 源码开发

```powershell
# 后端：项目根目录
mvn spring-boot:run
# 前端：另一终端
cd frontend
npm ci
npm run dev
```

application.properties支持DB_URL、DB_USER、DB_PASSWORD、SERVER_PORT、JWT_SECRET、CORS_ORIGINS；修改数据库主机/端口时也需覆盖应用DB_URL。开发前端可设API_TARGET覆盖代理目标。

## 5 构建和复验

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
# 首次浏览器测试安装
cd frontend
npx playwright install chromium
cd ..
node scripts/test-all.mjs
```

构建生成release/club-manage.jar与frontend/dist，业务测试结果在test。测试脚本使用独立club_manage_test、18081/15173端口，自动启动和停止测试进程。测试前后都会恢复测试库通用演示数据。不要手工把18081测试服务接到正式演示库。源码构建不默认执行依赖演示库的集成用例，完整复验脚本负责执行。

## 6 验证与故障定位

- 页面应出现登录页；学生2021010、管理层2021006、学生会2021007、教师T003，密码均123456。
- 未登录请求/api/clubs应返回统一JSON code=401；登录后带Bearer令牌可查询。
- 端口被占：启动脚本会停止，查看占用程序或先运行stop-all.bat，不会自动杀死其他程序。
- 数据库连接失败：确认MySQL运行，DB_URL/DB_USER/DB_PASSWORD正确，并已初始化。
- 找不到mysql：设置MYSQL_BIN；找不到java/node：安装并配置PATH。
- 审批业务错误：页面显示原业务提示，重复审批404属于正常防重，不是服务故障。
- 55例中的第50例存在原设计缺字段冲突，结果详见expected-results.md，不要为“全绿”修改原视图。
