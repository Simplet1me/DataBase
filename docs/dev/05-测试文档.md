# 测试文档（测试方案 + 演示数据）

> 目的：项目完成后，用一套**通用演示数据**验证全部业务逻辑；测试数据以 SQL 脚本形式长期保存，存放在工作空间 **test/** 目录（目录约定见 [test/README.md](../../test/README.md)），答辩演示与验收测试同源使用。
> 依据：[需求文档.md](../design/需求文档.md)（12 条约束、5 条闭环流程）、[procedures.sql](../design/procedures.sql)、[triggers.sql](../design/triggers.sql)、[views.sql](../design/views.sql)、[02-接口文档.md](02-接口文档.md)。

## 1 测试目标

1. 验证 **12 条全局约束**全部生效（见 §3 用例中的"验证点"列，逐条覆盖约束 1~12）；
2. 验证 **5 条闭环流程**端到端：建团、入社、退社、活动、解散；
3. 验证触发器/存储过程/视图与后端接口的联动（入社审批自动入社、sp_create_club、sp_dissolve_club、4 个视图查询**与更新**）；
4. 验证异常与边界：唯一键冲突回滚、SIGNAL 业务提示透传、换届原子性（B5）、学生会至少一人（C5）、并发审批控制、软删除（C7）；
5. 产出**测试报告**（need.md 考核4 要求）：按 §3 用例执行并记录到 `test/expected-results.md`，汇总为测试报告。

## 5 自动化测试方案（后端）

> 工程已含 `spring-boot-starter-webmvc-test`，实现阶段按此方案落地自动化用例，与 §3 手工用例互补。

### 5.1 接口层自动化（MockMvc）

- 覆盖 02 接口文档全部接口：正常路径 + 401/403/400 分支 + 1001/1002 业务分支；
- 数据策略：独立测试库 `club_manage_test`（初始化同 4 个 SQL），或 `@Transactional` 回滚式测试（注意触发器/SP 在事务内同样回滚，可用）；
- 典型断言：登录返回 token；审批同意后查询 club_member 断言新增记录（触发器联动）；换届接口失败断言原角色未变（原子性）。

### 5.2 数据库对象集成测试

- 用 JdbcTemplate/SimpleJdbcCall 直接调 5 个 SP：成功分支断言数据变化、失败分支断言 SIGNAL 错误码与消息；
- 触发器用例：用例 10、18~21 断言数据库状态；
- 唯一键冲突：断言捕获 DuplicateKeyException（1062）。

### 5.3 测试报告产出

- 执行 §3 全部用例 + §5 自动化结果，逐条记录到 `test/expected-results.md`（预期/实际/通过），最终汇总为《测试报告》（need.md 考核4），内容包括：测试环境、用例统计（55 例）、缺陷记录与修复、结论。
