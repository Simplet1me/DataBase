# 实现说明与文档差异

## 1 交付范围

已实现 M1～M7 的后端功能、F1～F6 对应的15个前端页面、通用演示数据、启动/停止/构建/测试脚本、接口测试与浏览器测试。保留原始数据库设计文件；默认后端8080、前端5173、数据库club_manage。独立验收使用club_manage_test及18081/15173端口，不操作机器上其他项目库。

依赖：Spring Boot 4.1.1、Java编译目标17、MyBatis starter 4.0.1、Auth0 java-jwt 4.6.1、Vue3、Element Plus、Vite8。MyBatis已实际启动并通过业务测试，无需切换JdbcTemplate。前端精确依赖版本由package-lock.json固定。

## 2 原文档存在的冲突及处理

### 2.1 缺少必要的接口契约

需求文档要求建团提交/进度、个人资料/改密/角色日志、历史退社记录、学生会操作日志，但02接口文档未给出路径；03文档明确要求补充空闲教师接口。本实现把这些已有需求补充写入02文档附录D，原有接口路径及请求字段保持不变。新增契约属于填补文档缺项，并非原02文档已定义的接口。社团详情采用基本信息对象增加notices，教师总览增加members/activities/notices。

### 2.2 换届会使原操作人立即失去过程权限

原sp_change_member_role在每一次调用时检查操作人是否仍为管理层。若所有过程调用始终传入原社长，第一步降级后，第二步必然失败。因此README规定的“所有步骤只传原操作人”与原过程无法同时成立。

实现保持单个@Transactional和所有角色写入经原过程：先验证真实请求人是现任社长，串行完成降级及新社长晋升；原社长降级后，过程内部操作参数使用事务内仍在职的管理层。若没有可保留的管理层，则先通过原过程临时赋予另一社员副社长角色作为权限桥接，完成后还原。临时桥接在事务外不可见，不占用额外表字段；最终日志统一记录真实请求人，移除仅由本事务产生的桥接日志，历史业务日志不受影响。

常规换届实际先降原社长、后升新社长，输出两条正式变更日志。无副社长、全部管理层降级、新社长也在降级名单等场景增加事务内临时步骤。这是为兼容不可修改的原过程所做的应用层适配，不能表述为README原算法逐字实现。任一步失败时角色及日志全部回滚，测试20～22及补充E3/E4/E8验证。

### 2.3 存储过程内部START TRANSACTION会提交外层事务

sp_create_club与sp_dissolve_club包含START TRANSACTION/COMMIT。MySQL不会建立嵌套事务，START TRANSACTION会隐式提交之前的审批UPDATE，单独加@Transactional不能恢复此前的审批字段。

实现使用数据库命名锁串行保护写业务，保留原过程。若过程执行失败，ApprovalRecoveryService通过独立事务恢复审批前状态快照，再透传原异常。测试26～28及E7直接核对恢复后的审批字段及无残留社团数据。

限制：这一兼容方案保障应用正常运行时的错误恢复；若进程在隐式提交后、补偿前崩溃，不能提供跨崩溃的严格原子性。要完全消除窗口，必须允许修改原过程的事务边界或增加持久恢复机制。当前遵守数据库对象不修改约束，未做这种改动。

依据：[MySQL隐式提交说明](https://dev.mysql.com/doc/refman/8.4/en/implicit-commit.html)。

### 2.4 教师可以先审，但流程要求学生会→教师

02文档5.2允许教师在学生会未审时先记录agree。为避免双方均同意却永久pending，应用在任意一侧成为第二个同意时调用原终审过程。正常页面流程仍按学生会→教师展示。双方各自审批UPDATE都带pending和final_status原状态条件，重复审批返回404。

### 2.5 第50例无法用原审批视图更新审批状态

v_join_apply_pending没有apply_status、approve_stu_id、reply_time字段。原第50例的UPDATE实际报1054。遵守不可修改视图约束，保留定义；替代验证包括：通过该视图更新暴露的apply_time并核对基表、通过v_stu_club_record更新退社信息、通过v_club_member_detail更新角色；入社审批仍只UPDATE join_apply，并验证原触发器自动入社。

因此测试结果明确记为“54个原用例通过；第50例原要求受限，替代验证通过”，不声称原55例全部严格通过。个人中心查询档案视图，主动退社接口通过v_stu_club_record更新club_member的退社字段，使现有操作界面具备视图查询与更新闭环；浏览器实测此操作。本次未额外开放让用户任意修改申请时间的接口。

### 2.6 MySQL8排序规则继承不同

原sql.sql建库指定utf8mb4_unicode_ci，但建表只显式指定utf8mb4。在本机MySQL8.4中表采用utf8mb4_0900_ai_ci，而过程VARCHAR参数默认继承库的unicode_ci，比较学号时报1267。

scripts/db.mjs在安装原过程前读取student表排序规则，临时使数据库默认排序规则一致；执行未经改写的原过程定义后恢复数据库原默认值。没有修改表/字段/索引、触发器/视图/过程的SQL正文。测试库名称替换仅发生在执行内存文本中。实际过程参数的继承元数据由安装环境决定，已与表对齐。不要直接跳过初始化脚本在MySQL8上盲目导入四个文件。

### 2.7 其他说明

- 原04文档宣称初始化可安全重复执行，但sql.sql按父表在前DROP，已有外键时会失败且存在数据破坏风险。交付初始化脚本遇到已有表直接停止；演示数据重置是单独、显式的操作。
- 原公告接口表把is_deleted=0写成置灰，和枚举及前端方案冲突。实现以0为有效、1为已删除并置灰。
- 需求允许学生主动退社，包括管理层；按原接口不增加社长退社限制。这可能留下无社长的社团，原设计本身未提供管理员强制补位接口。
- 全部SQL值使用绑定参数；固定XML语句标识只由服务代码选择。查询用视图投影Map，经统一转换保持驼峰字段、null和日期格式。未添加无业务用途的14份实体副本，也没有为了目录形式再拆同名Service接口/Impl。
- 小型课程系统用库级命名锁保护写请求，读请求不加此锁；这优先保证已有过程在并发下的正确性，不适合高吞吐生产写入。
