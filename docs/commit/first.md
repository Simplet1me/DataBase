数据库课程设计任务书

一、设计目标
1.	培养学生将理论知识应用于实际问题的能力。
2.	提升学生的团队协作、沟通协调和项目管理能力。
3.	增强学生的创新意识和实践能力，鼓励学生在实践中探索新方法、新技术。

二、考核内容
1.	调研和分析的能力：考核学生是否能够通过文献检索、行业调研、用户访谈等方式，全面收集与数据库设计相关的需求信息，包括功能需求、性能需求、数据安全需求等，并对收集到的信息进行系统梳理、归纳和分析，准确提炼出核心需求。 
2.	设计方案的能力：	考核学生是否能依据需求分析结果，科学选择数据库模型（如关系型数据库），合理设计概念模型（E-R图）、逻辑结构（规范化处理）与物理存储方案，并兼顾可扩展性、一致性和高并发访问等现实约束。
3.	数据库设计与实现能力：考核学生能否根据设计方案完成数据库的具体实现，包括数据表的创建（字段定义、数据类型选择、约束条件设置等）、索引设计与优化（如主键索引、唯一索引、复合索引的合理运用）、视图的创建与使用（用于简化复杂查询或实现数据访问控制），以及存储过程、触发器等数据库对象的编写，确保数据库结构既符合需求规范，又具备良好的性能和可维护性。
4.	撰写文档的能力：考核学生能否按照规范的格式和逻辑，完整撰写数据库设计过程中的各类文档，包括需求分析报告、设计说明书、测试报告以及用户手册，确保文档内容准确、条理清晰、语言规范，且能全面反映设计过程与成果。
5.	团队协作能力：考核学生在项目实施过程中与团队成员的协作效率与配合质量，包括是否能明确自身在团队中的角色定位（如需求分析负责人、设计方案制定者、代码实现人员或文档撰写者等），并主动承担相应责任；是否能与团队成员保持积极有效的沟通，及时分享设计思路、技术难点及解决方案；同时，还将考察团队整体的任务分配合理性、信息共享流畅度以及最终成果的协同贡献度，以此综合评估学生在实际项目环境中的团队协作能力。


三、课程设计要求
基于一个具体项目，分组完成数据库系统设计与实现，实现语言、框架不限。要求：
1. 基于一个具体项目，进行需求分析；
2. 对系统进行概念设计，画出系统不同粒度的ER图，如总ER图，子系统（模块）ER图等；
3. 设计系统数据库关系表，着重考虑完整性要求（主码、外码、属性类型与取值范围、触发器等）；
4. 为该数据库分配不少于两种用户角色，并给与不同权限。
5. 提供操作界面，实现基本的数据库查询与更新功能；
6. 定义视图，提供操作界面，实现视图的查询与更新功能。

四、考核方式
过程性考核20%+报告80%
	过程性考核：对实践课表现、进度、答辩等进行考核；
	报告：对作品质量、分工合理性、文档撰写水平进行考核。

五、报告要求
1.	封面：封面至少包含项目名称、专业、小组人员名单、指导老师、日期等内容；
2.	目录；
3.	需求分析：通过分析，列出项目目标、系统功能需求、非功能需求等；
4.	数据库设计：至少包括数据库ER图，关系表设计（主、外码，用户定义完整性），数据库角色及权限
5.	数据库实现：核心模块的界面及核心代码；
6.	系统测试：对于数据库的角色权限、安全性、完整性进行测试；
7.	项目分工；
8.	总结。
报告格式参考毕业论文格式要求执行。

六、考核时间
报告在11月1日前提交学习通系统，每组由组长统一提交一份。
